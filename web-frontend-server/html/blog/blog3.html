Storage, DNS, and Monitoring: MinIO, BIND9, Prometheus, and Grafana

Nguyễn Thành Nam – 523H0117

MinIO: S3-Compatible Object Storage

MinIO stores files as objects in buckets using an Amazon S3-compatible API. Port 9000 serves the API, and port 9001 serves the Console. The demo uses three buckets:

  • demo stores the basic demo file.
  • profile-pics allows anonymous downloads, so avatar.jpg is accessible through a direct URL.
  • documents remains private and stores the report PDF; downloads require authentication or a presigned URL.

BIND9: The Internal cloud.local Zone

The DNS server manages the cloud.local zone. Each A record maps a name to an IP address on cloud-net:

web-frontend-server IN A 10.10.10.10
app-backend         IN A 10.10.10.20
keycloak            IN A 10.10.10.40
minio               IN A 10.10.10.50

After editing the zone file, increment the SOA serial and restart the DNS container. Verify the record with dig @127.0.0.1 -p 1053 app-backend.cloud.local +short.

Prometheus and Node Exporter

Prometheus uses a pull model: every 15 seconds, it scrapes the /metrics endpoint of each target. Node Exporter exposes system metrics, while each Web server exposes Nginx metrics through its exporter. A target is UP when scraping succeeds. The current Node Exporter setup does not provide separate CPU and memory measurements for each container.

Grafana: Turning Metrics into Charts

The System Health of 523H0117 dashboard has three panels backed by PromQL queries. Their source metrics include:

CPU Usage (%)node_cpu_seconds_total

The datasource and dashboards are provisioned from files, so recreating the system loads the configured dashboards without manual setup.
